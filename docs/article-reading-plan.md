# 본문 기반 기사 설명 적용 계획

목표: 기존 수집 파이프라인에서 약 20건을 먼저 선별하고, 해당 글의 본문 근거로 설명 작성. 커밋·푸시 없음. 기존 UI·일간 발행 변경 유지.

구조: 수집·전처리 → 짧은 후보로 ID 선별 → 선별된 글의 RSS/HTTP 본문 확보 → 제한된 본문 입력으로 최종 설명. 별도 서비스·브라우저 자동화·차단 우회 없음.

## 상한과 수집 원칙

- 기사 최대 20건, 기사당 근거 텍스트 600자, 최종 근거 텍스트 전체 9,000자(토큰 예산 R3, 2026-10-15; 당초 1,500자·30,000자).
- 본문 HTTP 동시 실행 4개, 요청당 8초, 본문 확보 단계 전체 30초.
- 공개 HTTPS 주소만 접근. 사용자정보·비표준 포트·사설/로컬 IP 금지. DNS와 리다이렉트 주소 검증, 실제 연결 주소 고정.
- 같은 호스트에 요청을 몰지 않음. robots.txt 확인, 403·429·인증·유료벽·추출 실패는 우회나 재시도 없이 snippet으로 폴백.
- RSS 긴 본문을 먼저 활용. GitHub는 README, HF 모델은 모델 카드, 논문은 이미 받은 초록 우선. Google News는 페이지에서 확인 가능한 원문 링크만 사용, 비공개 RPC/차단 우회 없음.
- 추출 HTML은 스크립트·외부 리소스를 실행하지 않음. 모델에는 원문을 지시가 아닌 근거 데이터로 전달.
- 원문 실패 여부와 이유는 스냅샷·로그에 기록. 모달에는 피드 설명임을 간단히 표시.
- 입력·출력 사용량, 단계별 시간 기록. 본문은 로컬 캐시로 같은 URL 당일 재실행 시 재요청 최소화.

## 공유 인터페이스

- `RawItem.content?: string`: 피드/초록에서 확보한 긴 본문. 스냅샷에는 저장하지 않음.
- `ReadingInfo`: `{status: "body" | "snippet", via: "rss" | "web" | "readme" | "model-card" | "abstract" | "snippet", chars: number, reason?: string}`.
- `Item.reading?: ReadingInfo`: 모델이 아닌 코드에서 채움, 기존 스냅샷과 호환.
- `readArticles(items: RawItem[]): Promise<Map<string, ArticleEvidence>>`, `ArticleEvidence = {text: string, reading: ReadingInfo}`. `lib/read-articles.ts`에서 export.
- `ARTICLE_READING` 상수는 `config/sources.ts`에서 export. maxArticles 20, articleChars 600, totalChars 9000, concurrency 4, requestTimeoutMs 8000, totalTimeoutMs 30000, maxBytes 1500000, maxRedirects 3, minBodyChars 300, perHostDelayMs 250.
